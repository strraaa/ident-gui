# Приложение настроек Ident → Битрикс24

Десктопное приложение (PySide6) для настройки и обслуживания синхронизатора без
ручной правки `config.ini`. Служба синхронизации и приложение — два отдельных
процесса, работающих с одними и теми же файлами.

## Готовые сборки

Собранное приложение выкладывается в релизы репозитория —
`ident_settings_gui-vX.Y.Z_win64.zip` на вкладке **Releases**. Внутри архива папка
`ident_settings` целиком: распаковать и запустить `ident_settings.exe`.
Репозиторий приватный, поэтому для скачивания нужен вход в GitHub с доступом к нему.

### Как выпустить новую версию

Сборку делает GitHub Actions на Windows-раннере (`.github/workflows/release-gui.yml`),
своя Windows-машина для этого не нужна:

```powershell
git tag gui-v1.0.0
git push multi gui-v1.0.0
```

Через несколько минут релиз появится на вкладке Releases с прикреплённым архивом.
Прогон без публикации релиза — вкладка **Actions → Release GUI → Run workflow**:
архив осядет в Artifacts и будет храниться 90 дней.

Сборка идёт на Python 3.14 x64 — ровно под колёса, зафиксированные в
`requirements.lock` (`--require-hashes` не простит другую версию Python).

## Установка

Собрать самостоятельно:

```powershell
# Сборка
.\build_gui_exe.ps1          # → dist\ident_settings\ident_settings.exe

# Разместить рядом со службой
Copy-Item -Recurse dist\ident_settings "C:\Program Files\IdentBitrix24\settings"
```

Запускать **от имени администратора** — иначе будут недоступны перезапуск службы
и запись в `C:\Program Files`.

По умолчанию приложение открывает папку установки службы
(`%ProgramFiles%\IdentBitrix24`). Другую папку можно указать так:

```powershell
ident_settings.exe --workdir "D:\IdentBitrix24"
```

## Вкладки

| Вкладка | Назначение |
|---|---|
| **Состояние** | Состояние задачи планировщика, время последней синхронизации, сводка очереди, проблемы конфигурации. Кнопки запуска, остановки и перезапуска службы |
| **Подключения** | Доступ к SQL Server базы Ident и к порталу Битрикс24, проверка обоих подключений |
| **Поля** | Соответствие данных приёма пользовательским полям `UF_CRM_*`. Список полей подгружается с портала |
| **Стадии** | Статусы приёма Ident → стадии сделки, финальные и защищённые стадии, закрытые статусы лидов |
| **Синхронизация** | Интервал цикла, размер пакета, филиалы, параметры очереди, журналирование |
| **Очередь** | Что не доехало до Битрикса и почему: повтор выбранных записей, дослав всей очереди, выгрузка в CSV |
| **Логи** | Хвост журнала службы с фильтром по тексту и режимом «только ошибки» |

## Как это работает

**Настройки применяются только после перезапуска службы.** Конфигурация читается
один раз при старте процесса, поэтому после сохранения приложение предлагает
перезапустить задачу планировщика.

**Секреты не показываются.** Пароль БД хранится зашифрованным через Windows DPAPI.
Приложение видит только факт «значение задано и зашифровано»; ввод нового значения
перезаписывает старое. Шифрование выполняется с флагом `CRYPTPROTECT_LOCAL_MACHINE`,
поэтому значение, сохранённое администратором, читается службой, работающей от SYSTEM.

**Перед записью делается резервная копия** `config.ini.bak`, а сам файл пишется
атомарно под межпроцессной блокировкой `config.ini.lock`.

**Очередь правится напрямую.** Приложение использует ту же блокировку
`queue.json.lock`, что и служба. Но служба держит очередь в памяти и при своём
следующем изменении перезаписывает файл целиком, поэтому **перед массовыми
операциями с очередью службу лучше остановить** на вкладке «Состояние».

## Ограничения

- Управление задачей планировщика работает только под Windows и только с правами
  администратора. Остальные возможности доступны везде.
- Приложение не отправляет записи в Битрикс24 самостоятельно — оно только
  возвращает их в очередь, а отправляет служба в ближайшем цикле.
- Проверка подключений выполняется по сохранённым настройкам, поэтому изменения
  нужно сначала сохранить.
