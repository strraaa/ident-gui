Десктопное приложение (PySide6) для настройки и обслуживания синхронизатора Ident → Битрикс24. Служба синхронизации и приложение — два отдельных процесса, работающих
с одними и теми же файлами.

## Установка

### Готовая сборка

Собранное приложение выкладывается в релизы репозитория — архив
`ident_settings_vX.Y.Z_win64.zip` на вкладке **Releases**.

### Сборка из исходников

Требуется Windows и Python 3.14 x64 — ровно под колёса, зафиксированные в `requirements.lock`
(`--require-hashes` не простит другую версию Python).

```powershell
.\build_gui_exe.ps1
Copy-Item -Recurse dist\ident_settings "C:\Program Files\IdentBitrix24\settings"
```

Запускать **от имени администратора** — иначе будут недоступны перезапуск службы и запись в
`C:\Program Files`.

По умолчанию приложение открывает папку установки службы (`%ProgramFiles%\IdentBitrix24`). Другую
папку можно указать так:

```powershell
ident_settings.exe --workdir "D:\IdentBitrix24"
```

Выбранная папка, размер окна и открытый раздел запоминаются — при следующем запуске ключ не нужен.
Приложение использует единую тёмную тему; ключ `--theme dark` оставлен для совместимости.

## Разделы

Страницы разложены по трём разделам бокового меню. Наблюдение обновляется само и ничего не просит
сохранять, настройка копит правки до одной кнопки, диагностика ничего не меняет.

| Раздел | Страница | Назначение |
|---|---|---|
| **Наблюдение** | Обзор | Состояние задачи планировщика, время последней синхронизации, сводка очереди, проблемы конфигурации. Кнопки запуска, остановки и перезапуска службы |
| | Очередь | Что не доехало до Битрикса и почему: повтор выбранных записей, дослав всей очереди, выгрузка в CSV |
| | Журнал | Хвост журнала службы с фильтром по тексту и режимом «только ошибки» |
| **Настройка** | Подключения | Доступ к SQL Server базы Ident и к порталу Битрикс24, проверка обоих подключений |
| | Поля | Соответствие данных приёма пользовательским полям `UF_CRM_*`. Список полей подгружается с портала |
| | Стадии и воронка | Статусы приёма Ident → стадии сделки, финальные и защищённые стадии, закрытые статусы лидов |
| | Синхронизация | Интервал цикла, размер пакета, филиалы, параметры очереди, журналирование |

Страница с несохранёнными правками помечается точкой в меню, внизу окна показано их количество,
а перед записью приложение перечисляет, что именно изменится в `config.ini`.

## Как это работает

**Настройки применяются только после перезапуска службы.** Конфигурация читается один раз при
старте процесса, поэтому после сохранения приложение предлагает перезапустить задачу планировщика.

**Секреты не показываются.** Пароль БД хранится зашифрованным через Windows DPAPI. Приложение видит
только факт «значение задано и зашифровано»; ввод нового значения перезаписывает старое. Шифрование
выполняется с флагом `CRYPTPROTECT_LOCAL_MACHINE`, поэтому значение, сохранённое администратором,
читается службой, работающей от SYSTEM.

**Перед записью делается резервная копия** `config.ini.bak`, а сам файл пишется атомарно под
межпроцессной блокировкой `config.ini.lock`.

**Очередь правится напрямую.** Приложение использует ту же блокировку `queue.json.lock`, что и
служба. Но служба держит очередь в памяти и при своём следующем изменении перезаписывает файл
целиком, поэтому **перед массовыми операциями с очередью службу лучше остановить** на вкладке
«Состояние».

## Разработка

Настройки описаны декларативно в `gui/core/schema.py` — по одной записи на параметр: секция и ключ
в `config.ini`, тип значения, значение по умолчанию, подпись и подсказка. Это единственный источник
правды: из него собираются формы, проверки и подстановка умолчаний, поэтому новый параметр
добавляется одной записью, а не правкой нескольких вкладок.

Остальное ядро (`gui/core/`) не импортирует Qt:

| Модуль | За что отвечает |
|---|---|
| `ini_document.py` | чтение и запись `config.ini` без потери комментариев, порядка и чужих секций |
| `types.py` | типы значений: число, флаг, список, поле `UF_CRM_*`, секрет, соответствие статусов |
| `schema.py` | реестр параметров |
| `store.py` | значения, несохранённые правки, разница, резервные копии, запись |
| `validation.py` | проверки по параметрам и перекрёстные правила |

Интерфейс собран из тех же частей во всех страницах:

| Модуль | За что отвечает |
|---|---|
| `theme/tokens.py` | тёмная палитра, отступы и радиусы |
| `theme/stylesheet.py` | сборка QSS и QPalette, пометка элементов смыслом (`set_tone`) |
| `widgets/` | полоса сообщения вместо модального окна, отметка состояния, боковое меню |
| `pages/` | страницы разделов |
| `services/app_settings.py` | что приложение помнит между запусками |
| `services/logging_setup.py` | журнал приложения и перехват журнала службы |
| `services/errors.py` | необработанные ошибки: в журнал и в окно, а не в никуда |

Цвет нигде не задаётся на месте: страница помечает элемент смыслом — `set_tone(label, 'danger')`, —
а как выглядит опасность, решает тема.

Тесты написаны на `unittest` и не требуют установки зависимостей:

```bash
python -m unittest discover -s tests
```

Проверки сборки окна (`tests/test_gui_smoke.py`) пропускаются, если PySide6 не установлен.

Отдельно от тестов есть самопроверка — приложение собирает окно и сразу выходит:

```bash
python gui_main.py --selftest          # из исходников
ident_settings.exe --selftest          # из сборки
```

Код возврата 0 означает, что библиотеки Qt и плагины на месте. Это же делает `build_gui_exe.ps1`
после сборки, дважды: с `QT_QPA_PLATFORM=offscreen` и с обычной платформой. Смысл — поймать
перестаравшуюся чистку из `ident_settings.spec` на сборочной машине, а не у заказчика.

Состав дистрибутива описан в `ident_settings.spec`: список исключённых модулей и правила, по которым
из сборки выбрасываются библиотеки Qt, которые приложению не нужны. Иконка собирается из описания —
`python tools/make_icon.py` (нужен `rsvg-convert`), правится в `tools/make_icon.py`, а не в графическом
редакторе.

Журнал приложения — `%LOCALAPPDATA%\IdentSettings\ident_settings.log`. В папку службы приложение
не пишет: там журнал держит её собственный процесс.

## Обновление приложения

После открытия GUI автоматически проверяет последний стабильный релиз GitHub. При наличии новой
версии появляется полоса с кнопкой «Обновить». В разделе «Проверить обновления» можно вручную
запустить проверку, увидеть release notes и подтвердить перезапуск.

Перед установкой приложение скачивает архив во временную папку, проверяет SHA-256 из
`SHA256SUMS.txt`, отклоняет небезопасные пути в ZIP, запускает `--selftest`, а при ошибке
восстанавливает предыдущую установку. Релизы без опубликованной контрольной суммы не
устанавливаются.

## Ограничения

- Управление задачей планировщика работает только под Windows и только с правами администратора.
  Остальные возможности доступны везде.
- Приложение не отправляет записи в Битрикс24 самостоятельно — оно только возвращает их в очередь,
  а отправляет служба в ближайшем цикле.
- Проверка подключений выполняется по сохранённым настройкам, поэтому изменения нужно сначала
  сохранить.
- Одновременно работает только один экземпляр приложения: две копии, открывшие один `config.ini`,
  затёрли бы правки друг друга.
